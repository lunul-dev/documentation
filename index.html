GETTING STARTED / INTRODUCTION

Introduction to Lunul Foundation

Lunul Foundation (LF) is a high-throughput, horizontally scalable Layer-1 blockchain protocol engineered for institutional-grade decentralized finance, ultra-low latency orderbook execution, and secure cross-chain interoperability. By combining deterministic sub-second finality with advanced state separation, Lunul provides developers and global enterprises with an uncompromising execution environment.

Protocol Specification Highlights

Lunul achieves up to 65,000 transactions per second (TPS) with an average slot time of 200 milliseconds, ensuring zero mempool congestion during high-volatility market events.

Core Design Principles

The Lunul protocol architecture is built upon three foundational pillars designed to eliminate blockchain trilemma bottlenecks:

01

Hardware Scaling

Network throughput scales proportionally with validator hardware advancements, avoiding artificial software gas limits.

02

Deterministic Execution

Transactions declare all read/write states beforehand, allowing parallel CPU execution without race conditions.

03

Economic Predictability

Fee markets are localized per smart contract account, preventing congested NFT mints from spiking global gas fees.

Token Utility & Fee Economics

The native utility token $LUN powers the Lunul Foundation network across multiple economic layers: validator staking security, priority transaction fee burns, and on-chain governance proposals.

Priority Fee Burns

A percentage of base transaction fees are permanently burned, creating deflationary pressure proportional to network utilization.

Validator Rewards

Stakers earn protocol-subsidized inflation rewards by delegating $LUN to active consensus nodes, securing network finality.

State Separation Architecture

Unlike legacy monolithic chains where computation and data storage are bundled together, Lunul separates executable logic from persistent state storage.

Stateless Executable Programs

Smart contracts on Lunul are read-only programs containing immutable bytecode. They accept instructions, execute business logic, and mutate state externally.

Isolated Data Accounts

All runtime variables, user balances, and application data reside inside discrete storage accounts owned by specific programs.

Proof-of-State Consensus & VDFs

Lunul utilizes an optimized BFT consensus mechanism powered by cryptographic Verifiable Delay Functions (VDFs). This establishes a tamper-proof historical record of time without requiring validators to continuously gossip with one another.

Account & Rent Model

In Lunul, everything is stored in accounts—ranging from user wallets and token balances to deployed smart contract code and oracle feeds.

State Rent Exemption Mechanics

To prevent state bloat, accounts maintain a minimum balance exempting them from rent fees. If an account's balance falls below the rent-exempt threshold due to manual withdrawal, it is purged from validator RAM by the garbage collection daemon.

Parallel Transaction Execution Engine

Traditional blockchains process transactions sequentially, creating severe bottlenecks. Lunul implements a concurrency engine modeled after database concurrency control systems.

Transactions that do not overlap in their account state dependencies are processed concurrently across multi-core validator CPUs, allowing non-conflicting decentralized exchanges, lending pools, and NFT marketplaces to execute simultaneously in the exact same block.

Validator Hardware Requirements

Running a consensus validator node on Lunul requires enterprise-grade hardware to ensure high-speed state verification and block propagation across global relay networks.

Minimum Spec

  • • CPU: 16 Cores / 32 Threads @ 3.2GHz
  • • RAM: 128GB ECC DDR5
  • • Storage: 2TB NVMe PCIe 4.0 SSD
  • • Network: 1 Gbps Dedicated Uplink

Recommended Spec

  • • CPU: 32 Cores / 64 Threads @ 3.8GHz+
  • • RAM: 256GB ECC DDR5
  • • Storage: 4TB Enterprise NVMe (U.2)
  • • Network: 10 Gbps Low-Latency Uplink

Delegation & Slashing Mechanics

Token holders can delegate their $LUN tokens to any active validator without relinquishing custody. Validators sign blocks on behalf of their delegators and distribute proportional block rewards.

Slashing Conditions

Automatic protocol slashing triggers if a validator signs conflicting state transitions (double-signing) or attempts consensus manipulation, resulting in an immediate burn of up to 10% of staked collateral.

Smart Contract Environment

Lunul supports high-performance smart contracts compiled down to optimized eBPF bytecode. Developers can write secure decentralized applications utilizing robust system primitives.

Lunul SDK Quickstart

Interact with the Lunul network programmatically using the official TypeScript client library to deploy accounts, query state, and submit signed transactions.

client_transfer.ts TypeScript v6.2 
import { LunulClient, clusterApiUrl, LAMPORTS_PER_LUN } from '@lunul/web3.js';

// Initialize connection to Lunul Mainnet-Beta RPC cluster
const client = new LunulClient(clusterApiUrl('mainnet-beta'));

async function executeTransfer(senderWallet, recipientKey) {
  const transferAmount = LAMPORTS_PER_LUN / 10n; // 0.1 LUN
  
  const txSignature = await client.transferSOL({
    sender: senderWallet,
    recipient: recipientKey,
    lamports: transferAmount,
    commitment: 'confirmed'
  });

  console.log(`Transaction confirmed with signature: ${txSignature}`);
}

Security Audits & Testing Best Practices

All core programs maintained by the Lunul Foundation undergo rigorous formal verification and multi-firm cryptographic audits by top-tier security labs prior to mainnet deployment. Developers are advised to utilize the Lunul localnet test validator suite for end-to-end integration testing.
