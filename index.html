Introduction to Lunul Foundation & NullNet

Protocol specification · v2.4

The Lunul Foundation stewards the NullNet protocol—an enterprise-grade, privacy-focused blockchain network designed to bridge public-ledger transparency with complete financial confidentiality and high-throughput execution.

NullNet combines a Paris-targeted EVM execution environment (Chain ID 448000) with a native zero-knowledge UTXO shielding architecture. Developers write smart contracts using standard Solidity tooling while enabling secure, private transaction flows.

Traditional public blockchains expose wallet balances, transaction graphs, and contract interactions to public indexers. For corporate treasuries, gaming platforms, and commercial apps, this visibility compromises operational security. NullNet provides protocols with precise control over what financial data is publicly observed.

02

Cryptographic stack & dual-state architecture

EVM + UTXO model

NullNet operates across two distinct execution and state domains: an account-based EVM for smart contract execution, and a shielded UTXO subsystem for confidential value transfers. A robust bridge layer handles asset conversion, zero-knowledge proof verification, and state synchronization between domains.

Execution domain A

Paris EVM account state

Handles standard Solidity bytecode, contract storage, account balances, and public application logic with full transparency where required.

⇄
Shielding domain B

ZK-UTXO pool

Processes private notes, cryptographic commitments, and nullifiers, enforcing double-spend protection without exposing transfer amounts or counterparty addresses.

Wallet networking & IP privacy

NullNet client connections route through secure RPC endpoints and encrypted relays designed to protect client network metadata. Production nodes secure JSON-RPC interfaces behind authenticated proxies, strict CORS policies, and TLS termination.

Commitments, proofs & encrypted payloads

NullNet leverages Pedersen commitments over the BN254 curve, AES-GCM authenticated payload encryption, and Ed25519 signatures to establish robust cryptographic privacy guarantees.

C = r · G + v · H

Where v represents the committed transaction value, r is the secret blinding factor, and G and H are independent generator points on the BN254 elliptic curve.

Consensus, finality, fees & state management

Geth / Clique PoA

NullNet runs on a customized Go-Ethereum (Geth) Clique Proof-of-Authority consensus engine operating under Chain ID 448000, ensuring authorized signer governance, rapid block times, and high transaction reliability.

State lifecycle

State rent & pruning

Active state management utilizes periodic storage optimization and cold-snapshot migration to maintain high I/O efficiency across validator nodes.

Transaction economics

LUN gas & treasury routing

LUN serves as the native gas asset with 18 decimal precision. Transaction fees power validator rewards, with protocol treasury routing and dynamic fee burning active on-chain.

Node initialization example

Initialize and launch a NullNet validator node using the official Geth client binary:

Shell executionSecure signer setup
# Initialize the data directory with the official genesis file
geth --datadir ./data init genesis.json

# Launch the Geth node with secure RPC binding
geth --datadir ./data \
  --networkid 448000 \
  --http --http.addr 127.0.0.1 --http.port 8545 \
  --ws --ws.addr 127.0.0.1 --ws.port 8546
Security warning: Always bind RPC endpoints to localhost or private interfaces behind authenticated reverse proxies (such as Nginx). Never expose unauthenticated administrative interfaces or raw validator keys on public networks.
Validator security & slashing

NullNet enforces strict protocol rules against double-signing and invalid proof submissions, with automated validator jailing and stake slashing protocols managed at the consensus layer.

Solidity compiler & EVM compatibility

Paris EVM target

NullNet targets the Paris EVM ruleset. Contracts must be compiled explicitly for the Paris target to ensure full execution compatibility across all validator nodes.

Hardhat configurationEVM target setup
module.exports = {
  solidity: {
    version: "0.8.20",
    settings: {
      optimizer: { enabled: true, runs: 200 },
      evmVersion: "paris"
    }
  }
};
Standard ERC-20 contractSolidity implementation
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/access/Ownable.sol";

contract CustomManagedToken is ERC20, Ownable {
    constructor(
        string memory name_,
        string memory symbol_,
        uint256 initialSupply
    ) ERC20(name_, symbol_) Ownable(msg.sender) {
        _mint(msg.sender, initialSupply * (10 ** decimals()));
    }

    function mint(address to, uint256 amount) external onlyOwner {
        _mint(to, amount);
    }
}

Developer FAQ

Quick reference
What is the NullNet Chain ID?

NullNet operates on Chain ID 448000. Configure your Web3 wallet and development tools accordingly.

Which EVM target should smart contracts use?

Contracts must target the Paris EVM ruleset. Explicitly set evmVersion: "paris" in your compiler settings.

Are all deployed smart contract balances private?

No. Standard EVM contracts operate transparently on account state. Privacy features are explicitly enabled via NullNet's zero-knowledge shielded transaction protocols.

How is network security maintained?

NullNet utilizes a Geth-derived Clique Proof-of-Authority consensus engine with high-performance validators and automated slashing conditions.

Where can I access developer tools and portals?

Access the official developer workspace and tools via the Lunul Portal.
