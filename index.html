01. Introduction to Lunul Foundation & NullNet

Protocol Spec v2.4

Lunul Foundation (LF) architects and governs the NullNet protocol—an institutional-grade, privacy-centric blockchain network engineered specifically to solve the existential trade-offs between public ledger transparency, corporate confidentiality, and high-performance throughput. Operating as a cryptographic "VPN for your Web3 Wallet", NullNet completely isolates user identities, account balances, and contract invocation flows from public surveillance algorithms, state-level monitoring, and competitive intelligence harvesting.

Public networks like Ethereum, Solana, and Arbitrum broadcast every account state change, wallet balance, and contract parameter directly to public indexers, MEV sandwich bots, and address-clustering firms. For multinational corporations, financial institutions, DAOs managing treasury funds, and high-net-worth individuals, this total transparency creates unacceptable security vulnerabilities, front-running losses, and commercial intelligence leaks.

NullNet addresses these systemic vulnerabilities by combining a native Paris EVM execution runtime (Chain ID 448000) with a parallelized zero-knowledge UTXO (ZK-UTXO) shielding pool. Developers can seamlessly deploy standard Solidity smart contracts that execute with deterministic BFT finality under complete end-to-end cryptographic shielding.

// Core Architectural Pillars

1. Total Payload Shielding

Transaction parameters, transfer quantities, and address relationships are encrypted via AES-GCM and signed using Ed25519 keypairs before entering the validator P2P gossip layer.

2. Turnkey EVM Tooling

Write standard Solidity code using Remix, Hardhat, or Foundry targeting the Paris hardfork without needing custom ZK domain-specific languages or exotic virtual machines.

3. Sub-400ms BFT Finality

The Geth-derived Clique Proof-of-Authority engine delivers instant, non-revertible block finality in under 400 milliseconds, eliminating MEV reorgs and front-running.

02. Cryptographic Stack & Dual-State Architecture

Hybrid Account & UTXO Engine

Legacy privacy networks routinely force developers into stark, uninviting choices: either write logic in obscure, unproven domain-specific languages (like Cairo, Noir, or Leo), or sacrifice private state management altogether. NullNet resolves this dilemma by pairing a full EVM account state machine with a parallel zero-knowledge UTXO engine:

Account State Engine (Paris EVM)

Executes complex smart contract bytecode, manages ERC-20 token logic, handles DEX liquidity pools, and processes automated state transitions using standard Solidity semantics.

Shielded UTXO Engine (ZK-SNARK)

Processes blind token transfers, verifies Pedersen commitments, manages nullifier trees, and shields transaction graph data from external observers.

// Wallet VPN & IP Concealment Protocol

When users connect Web3 provider extensions (such as MetaMask or Phantom) to the NullNet JSON-RPC endpoint (http://16.171.242.167:8545), all outbound RPC queries, gas estimations, and signed transactions are wrapped inside an encrypted WebSocket gossip protocol. The client acts as an ephemeral node participant, shielding user IP addresses, geographic metadata, and local balance records behind randomized validator relays.

// Pedersen Commitments & Homomorphic Encryption

Mathematical Value Commitment Equation:

C = r · G + v · H

Where v represents the confidential transaction value, r is a cryptographically secure 256-bit blinding factor, and G, H are fixed generator points on the Curve25519 / Ed25519 elliptic curve. Consensus validators verify that input commitments strictly balance output commitments without ever revealing v to the public ledger.

03. Clique BFT Consensus, Fees & State Rent

Geth / Go-Ethereum Core

NullNet operates a customized Go-Ethereum (Geth) Clique Proof-of-Authority (PoA) engine optimized specifically for sub-second block creation and zero-reorg block confirmation. Genesis parameters enforce Chain ID 448000 across all active validator nodes.

// State Rent & Pruning Protocols

To prevent unbounded state growth and keep node memory footprints fast, NullNet enforces a state storage rent mechanism. Active contract storage slots consume micro-fractions of native LUN per epoch. Stale or abandoned storage slots are automatically migrated to off-chain cold snapshots, preserving validator RAM for active transaction execution.

// Gas Routing & Treasury Protocol

Transactions consume native LUN gas dynamically calculated from EVM opcode execution complexity, ensuring optimal block space utilization, low network latency, and predictable gas accounting for high-throughput smart contract interactions.

05. Shielded Solidity & Compiler Guidelines

COMPILER COMPATIBILITY RULES

MANDATORY COMPILER TARGET SETTING: NullNet is strictly locked to the Paris EVM hardfork. Default configurations in newer Solidity compilers (such as solc 0.8.20+) target the Shanghai EVM, which emits the PUSH0 opcode (0x5f). Because NullNet enforces Paris rules, deploying bytecode that contains PUSH0 will result in node transaction execution failure (invalid opcode).

⚠️ Required Solc Configuration Settings:

  • Solidity Version: 0.8.20 (or lower)
  • EVM Target: paris (Manually set in Remix, Hardhat, or Foundry)
  • Optimizer: Enabled (200 Runs)
